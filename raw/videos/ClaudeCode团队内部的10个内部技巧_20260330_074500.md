## 📌 核心重點

1. **同時跑 3-5 個 Claude Code 會話** — 用 Gatebox 隔離上下文，各自跑不同任務（A 組實現、B 組寫測試、C 組做重構），像管理 AI 團隊而非單人寫碼
2. **用 Claude Code 做重寫，不只是開始** — 團隊用 Shell 腳本封裝高频操作，如自動清理重複代碼、整合最近 7 天的 Stack Overflow、Google Drive、3 個任務為上下文
3. **做了不止一次的事就封裝成流程** — 不靠記憶重複操作，把 AI 交互方式本身變成可重複的腳本
4. **用 CLI 工具優先於 MCP** — CLI 更簡單、更容易調試、本地行為一致；MCP 只用於需要雙向通信的場景
5. **Claude Code 當學習工具** — 用它讀代碼、畫架構圖、生成 HTML 探索器理解陌生代碼庫，不只是執行工具
6. **平行不是更快，任務分配才是核心** — 不要讓多個 Agent 同時改同一文件（後寫的會覆蓋），先從非代碼任務（PR review、調查、文檔）開始平行化
7. **經常更新 Claude Code** — 小版本更新常包含重大改進，如大文件分割支持、大型工具輸出優化
8. **把 Claude 當可被塑造的協作者** — 提示詞可選擇、規則可被 AI 自己寫、流程可封裝成技能，持續優化人機協作界面

## 📝 完整轉錄

NCRP的内部有个人叫做Boris Qianning，上个月他先分享了自己个人去使用Cloud Code的使用方式，他是Cloud Code的核心工程师。最近又整理一份团队内部怎么去使用Cloud Code的清单一共有10条。

第一条是要去同时去跑3到5个Claude Code。团队的第一条技巧就是不要只去看一个Claude Code的对话，要同时去开3到5个。他们的做法就是用Gatebox去，每一个是一个独立的工作幕路，运行各自的Claude的会话。然后呢用在这一币这些这样的效的一个别名一件去切换。有人甚至还专门有一个枷毒的分析我去专门用来去看日子。

第二条就是拼贸的，这个不只是用来开始更加是用来去做重写。团队用Sedgecom本来去封装高频操作。举个例子通过弹幕每次会话结束前找出并且清理重复弹码。还有更复杂的就是一个Kandex弹部的秘密，自动去拉举最近的7天的Stack小鞋、Google Drive的文档、3NN任务和给他他的提教，会终成一份上下文让Claude在新的会话里面快速去了解最近发生什么。

第三条：如果一件事你做了不止一遍就把它变成一个可重复的流程，而不是靠记忆每次就从做。以前这个原则主要是用在弹马上，现在他团队用于以和AI的交互方式的文本本身。

第四条：需要先对自己的工作留意清晰的人质，知道什么是真正重复操作，然后才有东西可以封装。

第五条就是用CLI工具不要去一来MCP。团队用MCP是急上了CLI可以让Claude直接去读写CLI。理由就是CLI更简单更容易调势在本地和CLI的行为是一致的。

第六条就是把Claude当成一个学习工具不只是一个执行工具。具体技巧就是你可以让Claude画代码架构图和交互式的HTML探索器帮助你理解一个陌生代码库。还有概念图模式让Claude帮你去画出一个领域里面的知识结构。

第七条：可以让Claude自己学习新工具。只要工具有Help文档Claude就会学会去用它。

第八条：平行不得更快，任务分配才是核心。不要让多个Agent的同时去修改同一顿文件因为结果是最后写入者是货圣的。团队的建议就是先从非代码任务开始去平行，比如说像PR6像8个调查像文脑整理。

第九条：更新一定要经常更新。小版本更新经常会包含非常有用的改动。

第十条：把Claude当成一个可以被塑造的协作者而不是一个固定的工具。
